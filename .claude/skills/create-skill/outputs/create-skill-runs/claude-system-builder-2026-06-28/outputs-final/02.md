## 1. Visão Geral do Sistema
API REST para um SaaS B2B de gestão de projetos. Permite que times criem workspaces, projetos e tarefas, com colaboração entre membros via convites por email. Consumida pelo frontend existente via HTTP.

## 2. Stack Técnica
- Linguagem: Node.js + TypeScript [DEFAULT: TypeScript 5.x — confirmar versão]
- Framework: Express [DEFAULT: Express 4.x — confirmar versão]
- Banco de dados: PostgreSQL [DEFAULT: versão 15 — confirmar]
- Hosting: Railway [DEFAULT: single-region — confirmar região]
- CI/CD: none (fora do escopo)
- Pacotes adicionais: `pg`, `jsonwebtoken`, `zod`, `@sendgrid/mail`, `bcrypt`

## 3. Componentes e Responsabilidades
- **API server** (Express): gerencia auth, todos os endpoints REST, validação via Zod, aplica escopo por workspace.
- **PostgreSQL**: armazena todo o estado persistente — usuários, workspaces, projetos, tarefas.

## 6. Restrições de Segurança
- Modelo de auth: JWT [DEFAULT: HS256 — confirmar algoritmo], header `Authorization: Bearer <token>` em rotas protegidas.
- Permissões: toda query filtra por `workspace_id`. Role 'admin' obrigatório para convites, gestão de membros e deleção de workspace.
- Validação de entrada: bodies validados com Zod antes de qualquer lógica. Rejeitar campos desconhecidos. Token de convite deve ser verificado antes de aceitar.
- Segredos: `JWT_SECRET`, `DATABASE_URL`, `SENDGRID_API_KEY` em variáveis de ambiente.

## 7. Fases de Implementação

**O Claude Code constrói:**

- Auth: `POST /auth/register`, `POST /auth/login` (retorna JWT)

## 8. Regras DO NOT
- Nunca hardcode secrets — usar variáveis de ambiente.
- Nunca usar `any` em TypeScript.
- Nunca bypassar o middleware de auth em rotas protegidas.
- Nunca interpolar strings em queries SQL — usar `pg` parametrizado.
- Nunca acessar dados de outro workspace — filtrar por `workspace_id` na query.
- Nunca implementar funcionalidades além do escopo acima sem confirmação.
