## System overview
Notification service for an existing B2B SaaS. Sends email (SendGrid) and SMS (Twilio). Integrates with existing JWT auth system.

## Tech stack
- Node.js + TypeScript
- PostgreSQL (existing instance)
- BullMQ (Redis-backed queue)
- pg (raw SQL — no ORMs)

## Components
- REST API: receives notification requests, validates sender identity
- Worker: processes queue, calls SendGrid/Twilio
- Admin panel: out of scope (other team)

## Security Constraints
- Authentication: verify sender exists in our system before any notification is sent (JWT check)
- No notification allowed without verified user
- Secrets in environment variables only — never hardcoded

## DO NOT
- DO NOT use ORMs — raw SQL with pg only
- DO NOT hardcode API keys or secrets
- DO NOT implement the admin panel — that is another team's responsibility
- DO NOT add unverified sender dispatch paths
