# Avaliação: a skill `user-stories` deve disparar aqui?

**Não.** A skill não deve gerar histórias de usuário para este input.

**Por quê:** A descrição da skill e a seção **Out of Scope** são explícitas: *"Escrever ou redigir o PRD em si → use `/claude-system-builder` (sistemas) ou `/lovable-prompt` (apps Lovable)"*. O input do usuário não pede histórias de usuário nem aponta um PRD/spec já existente para quebrar — ele pede exatamente a coisa que a skill declara não fazer: **escrever o PRD completo do zero**. Não há gatilho de user-stories aqui ("criar histórias", "critérios de aceite", "transforma esse PRD em stories" etc.), e mesmo que houvesse, o Out of Scope teria prioridade sobre tentar encaixar isso no Step 1 Caso B, porque o pedido não é "não achei PRD, gera as histórias mesmo assim" — é "quero que você escreva o PRD".

---

## Resposta que a skill produziria

Essa skill (`/user-stories`) não escreve PRDs — ela gera histórias de usuário em Gherkin a partir de um PRD/spec que já existe (na conversa ou em `outputs/`) ou de uma feature já descrita verbalmente. Redigir o PRD completo do zero está fora do escopo dela (ver seção Out of Scope da skill).

Para a feature de assinatura recorrente, o próximo passo é gerar o PRD com uma destas skills:

- **`/claude-system-builder`** — se a feature envolve um sistema/backend completo (cobrança recorrente, integração com gateway de pagamento, gestão de ciclo de cobrança, webhooks de status de assinatura, banco de dados de planos/assinantes).
- **`/lovable-prompt`** — se o app é construído no Lovable (React + Supabase) e a assinatura recorrente é uma feature dentro desse app.

Se ainda não estiver decidido qual dos dois caminhos faz mais sentido, `/prd-router` pode ajudar a classificar isso depois que houver ao menos um rascunho de PRD — mas como ainda não existe nenhum documento, o ponto de partida é uma dessas duas skills de geração de spec.

Assim que o PRD de assinatura recorrente existir (colado na conversa, ou salvo em `outputs/prds/` ou `outputs/claude-system-builder-runs/`), volte para `/user-stories` que eu:
- Extraio os requisitos funcionais e regras de negócio do PRD, citando a seção de origem de cada um
- Quebro a feature em épicos e histórias no formato INVEST
- Escrevo critérios de aceite em Gherkin (Dado/Quando/Então) para cada história
- Marco estimativas não confirmadas com `[DEFAULT: X pts — confirmar com o time]`
- Checo se há integração Linear/Jira conectada para já criar os tickets, ou salvo em markdown
